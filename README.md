# 谷歌云端硬盘管理（Chrome 扩展）

在 Google Drive 页面右侧悬浮面板中，批量管理文件夹内的文件；并在表格、文档等页面支持图片悬停放大。

## 功能

- 自动加载当前云端硬盘文件夹
- 图片缩略图预览，悬停放大预览
- 通过云端硬盘原生播放器预览视频
- 点击视频卡片可固定大预览并尝试自动播放
- 多选文件并移动到目标文件夹
- 批量删除：把所选文件移入云端硬盘回收站（可恢复，不是永久删除）
- 下载所选文件；多文件打包为 ZIP（单个或合计超过 30MB 时请在云端硬盘页面直接下载）
- 复制所选文件链接（可选是否包含文件名）
- 检查 `christiancagfr-alt/Google-Drive-manager` 的正式版更新；下载前校验同名 `.sha256`（若发布里有）。扩展不会自动覆盖安装
- 在当前文件夹批量创建子文件夹
- 按文件名自动分类，创建分类文件夹并移动文件
- **表格 / 文档 / 邮件等页面：鼠标悬停预览图或云端图片即可放大**（Alt+点击固定，Esc 关闭）

## 授权方式

扩展有两种授权，在弹窗的「授权方式」里切换。默认仍是 Apps Script，已经部署好的用户不用改。

### 自己的 Google 账号（点「授权」弹出登录）

弹窗选择「服务账号」后，选择授权文件，再点绿色「授权」。会弹出 Google 登录窗口。用你自己的账号点允许后，扩展用这个账号管理云端硬盘，不用把邮箱贴进文件夹共享。

第一次要在 Google Cloud 准备一个 OAuth 客户端：

1. 打开 Google Cloud，创建或选中项目，启用 Google Drive API
2. 凭据 → 创建凭据 → OAuth 客户端 ID
3. 应用类型选「网页应用」
4. 已获授权的重定向 URI 填 `https://eakajhoinfbdkfhelckcmpogflampblj.chromiumapp.org/`，末尾斜杠要保留。扩展清单里已写入固定公钥，所有人的插件 ID 都是这一条，不随文件夹位置变化
5. 把客户端 ID 贴进授权窗口，或在弹窗里选择下载的客户端 JSON，再点「弹出 Google 登录」
6. 客户端 ID 只需保存一次。之后点「授权」会直接弹出 Google 登录

客户端类型用「网页应用」。把客户端 ID 写进扩展目录的 `oauth-config.js` 后，其他人点「授权」会直接弹出 Google 登录。桌面应用和「Chrome 扩展程序」类型不会登记这条回调，Google 会返回错误 400：`redirect_uri_mismatch`。

刷新令牌只写入这台电脑的 `chrome.storage.local`。客户端 ID 放在 `oauth-config.js`，所有安装共用。内容脚本拿不到刷新令牌和私钥。不要把私钥放进扩展目录。

### 服务账号（把文件夹共享给邮箱）

也可以只导入服务账号 JSON。这种密钥不能弹出 Google 的同意窗口。导入后如果还没有完成上面的登录，请把要管理的文件夹共享给 JSON 里的 `client_email`，权限选「编辑者」。两种都保存时，优先用你登录的 Google 账号。

扩展拒绝 JWT 里的 `sub`，不做域范围委派。若密钥泄露，到 Google Cloud 删除该密钥。更新、口令、测试连接和这段说明都在弹窗的「更多」里。

### Apps Script（用户自授权）

本模式采用 **用户自授权**。

Chrome 扩展调用 Apps Script 网页应用。部署时应设置为：

```text
执行身份：访问网页应用的用户
具有访问权限的用户：拥有 Google 账号的所有用户
```

在此配置下：

- 每位 Google 用户为自己授权云端硬盘访问
- 列表、移动、创建文件夹、下载、自动分类均在该用户权限下运行
- 用户只能管理自己账号可访问的文件和文件夹
- 不会用你的账号去操作他人云端硬盘

若扩展提示需要授权，请点击悬浮面板中的「授权云端硬盘」，或弹窗中的「授权云端硬盘」。会在当前 Chrome 配置中打开带 `?action=auth` 的网页应用地址。登录并授权后，回到云端硬盘页面点击「加载」。

## HTTP 404 排查（最近无法使用时优先看这里）

界面提示 `请求失败：HTTP 404` 时，**几乎都是网页应用部署地址失效**，不是扩展本身“突然坏了”。常见原因：

1. 在 Apps Script 里点了「新建部署」而不是「管理部署 → 编辑 → 新版本」→ **URL 变了**，旧地址会 404  
2. 旧部署被归档 / 删除  
3. 粘贴了编辑器地址、`/dev` 测试地址、或云端硬盘文件夹地址  
4. Google Workspace 账号应使用  
   `https://script.google.com/a/macros/你的域名/s/部署ID/exec`  
   而不是个人版路径

### 正确修复步骤

1. 打开 <https://script.google.com/>，进入对应项目  
2. 右上角 **部署 → 管理部署**  
3. 找到类型为 **网页应用** 的部署，复制最新 URL（必须以 `/exec` 结尾）  
4. 若后端代码有更新：点该部署右侧铅笔 → 版本选「新版本」→ 部署（**不要新建部署**，以免换 URL）  
5. 打开扩展弹窗，粘贴地址 → **保存地址** → **测试连接**  
6. 若测试成功但仍无法列表：点 **授权云端硬盘**，登录并允许权限  
7. 在 `chrome://extensions/` **重新加载扩展**，强制刷新 Drive 页面后再点「加载」

地址格式示例：

```text
# 个人 Google 账号
https://script.google.com/macros/s/你的部署ID/exec

# Google Workspace
https://script.google.com/a/macros/company.com/s/你的部署ID/exec
```

不要粘贴：

- 云端硬盘文件/文件夹地址  
- Apps Script 编辑器地址  
- 以 `/dev` 结尾的开发地址（仅调试可用）

扩展弹窗提供 **测试连接**（调用 `?action=ping`）：

- 404 → 地址/部署有问题  
- 返回 HTML / 提示授权 → 需要先点授权  
- 返回 `pong` → 部署可用，再授权后即可列表

## Apps Script 部署步骤

1. 打开 <https://script.google.com/>
2. 新建项目（或打开已有项目）
3. 将 `apps-script-backend.gs` 完整复制到 `Code.gs`
4. 使用仓库中的 `appsscript.json` 内容更新清单（可在项目设置中查看）
5. 部署为「网页应用」
6. 「执行身份」选择「访问网页应用的用户」
7. 「谁可以访问」选择「拥有 Google 账号的所有用户」（或更窄但仍覆盖目标用户的选项）
8. 复制部署后的网页应用地址，必须是 `/exec` 结尾
9. 打开扩展弹窗，粘贴该地址并保存
10. 点击「测试连接」，再点「授权云端硬盘」

每当 `apps-script-backend.gs` 或 `appsscript.json` 变更后，请 **在原部署上发新版本** 并更新扩展里的地址（若 URL 变了）。

2.4.0 起，列表、移动、下载、创建文件夹、自动分类和删除都改为 **POST JSON**。只更新扩展、不重新部署后端时，这些操作会失败。`ping` 和授权页面仍是 GET。

可选：在 Apps Script「项目设置 → 脚本属性」添加 `DRIVE_MANAGER_TOKEN`，并在扩展弹窗保存同一个口令。未设置时保持兼容。口令只保存在本机，不会放进扩展源码。已经泄露的 GitHub 令牌必须在 GitHub 作废并重新生成。

## 图片 / 视频悬停放大（仅表格与文档）

**仅在以下页面启用**（云端硬盘文件夹页面不启用，避免干扰管理操作）：

- Google 表格（`docs.google.com/spreadsheets/...`）
- Google 文档（`docs.google.com/document/...`）

支持：

- 单元格 / 正文中的云端硬盘链接、缩略图 → 悬停放大图片  
- 视频类 Drive 链接（扩展名或文件名可识别）→ 悬停显示云端原生预览播放器  
- 缩略图加载失败时，可回退到 Drive 文件预览（部分视频/文件）

操作：

- 鼠标悬停：快速显示放大预览（位置固定在源内容旁，不跟鼠标拖走）  
- **Alt + 点击**：固定预览；视频固定后可点击播放  
- **Esc** 或点 ×：关闭预览  

说明：部分表格单元格由 canvas 绘制；带 Drive 链接或缩略图时体验最佳。云端硬盘右侧管理面板仍使用自带预览，不受此功能影响。

## 自动分类规则

后端扫描当前文件夹中的文件名，按共享前缀分组。

示例：

```text
001-ZB-CategoryName-part1.mp4
002-ZB-CategoryName-part2.mp4
003-ZB-CategoryName-part3.mp4
```

会归类到：

```text
ZB-CategoryName
```

规则说明：

- 去掉开头编号，如 `001-`、`002-`、`003-`
- 取接下来由 `-` 或 `_` 分隔的两段作为分类名
- 同一分类至少 2 个文件才会处理
- 若分类文件夹已存在则复用
- 将文件移动到对应分类文件夹

## 扩展安装

1. 打开 `chrome://extensions/`
2. 开启「开发者模式」
3. 点击「加载已解压的扩展程序」
4. 选择本扩展文件夹
5. 点击扩展图标。Apps Script：粘贴网页应用地址 → 授权。自己的账号：选择授权文件 → 授权，在弹出的 Google 窗口里点允许。只导入服务账号时，把文件夹共享给该邮箱
6. 打开云端硬盘文件夹页面，使用右侧悬浮面板

代码更新后请在 `chrome://extensions/` 点「重新加载」，并强制刷新已打开的页面。

## 批量删除

1. 勾选文件，或点击「全选」
2. 点击「删除所选（移入回收站）」并确认
3. 文件进入云端硬盘回收站，可从回收站恢复

一次最多 50 个。扩展不会调用永久删除。

## 自动更新

扩展弹窗的「检查更新」读取 GitHub 仓库 `christiancagfr-alt/Google-Drive-manager` 的最新正式版。发现新版本后，徽章显示 `NEW`，云端硬盘面板和弹窗都可以下载 zip。

- 只接受该仓库、该版本号对应的 `google-drive-manager-vX.Y.Z.zip`
- 若发布里有同名 `.sha256`，校验不符就拒绝保存
- 下载完成后需要手动解压覆盖扩展目录，再到 `chrome://extensions/` 重新加载
- 仓库若是私有的，匿名请求会失败。可在弹窗保存只读 GitHub 令牌（`github_pat_` 或 `ghp_`），令牌只留在本机
- 源码里没有 GitHub 令牌。令牌一旦粘贴过又不再使用，请到 GitHub 作废

## 复制链接

1. 勾选文件，或点击「全选」
2. 按需勾选「复制时包含文件名」
   - 关闭：只复制链接，每行一条
   - 开启：复制「文件名 + 链接」，粘贴到表格可分成两列
3. 点击「复制链接」，再粘贴到表格或文档

## 后端接口

Apps Script 后端支持：

- `ping` / `health`：GET，连通性探测（不访问 Drive，用于排查 404）
- `auth`：GET，触发用户授权
- `list`：POST，列出文件与子文件夹
- `move`：POST，移动文件
- `download`：POST，下载/打包
- `delete`：POST，把文件移入回收站
- `createFolders`：POST，批量创建文件夹
- `autoClassify`：POST，按文件名自动分类

一次最多处理 50 个文件或 50 个新建文件夹。

## 安全预检

本仓库包含 GitHub 安全相关自动化：

- CodeQL 代码扫描：使用仓库 **Default setup**（勿再添加高级 `codeql.yml`，否则会与默认设置冲突导致失败）
- Dependabot 更新 GitHub Actions：`.github/dependabot.yml`
- 浏览器扩展发布打包与构建证明：`.github/workflows/release.yml`（推送 `v*` 标签触发）
- 安全说明：`SECURITY.md`
- 发布检查清单：`SECURITY_RELEASE_CHECKLIST.md`

审核提交参考：

- 审核类型：`browser_extension`
- 项目地址：`https://github.com/christiancagfr-alt/Google-Drive-manager`
- 当前清单版本：`2.5.0`（已发布标签仍以 GitHub Release 为准，写这份说明时最新标签是 `v2.3.5`）
- 发布资源：`google-drive-manager-v<版本>.zip` 与同名 `.sha256`

发布前请确认：

1. 代码已推送到 GitHub
2. 在仓库设置中启用密钥扫描、推送保护、Dependabot 告警与代码扫描
3. CodeQL 工作流运行成功
4. 创建版本标签，如 `v2.3.5`
5. 确认发布工作流上传了 ZIP 并生成产物证明
6. 处理所有开放的安全告警，尤其是严重问题

## 说明

- 视频预览使用 `https://drive.google.com/file/d/{fileId}/preview`
- 视频通过云端硬盘原生播放器预览，扩展不会转换原始格式
- 浏览器自动播放策略可能阻止未静音自动播放；此时点击固定预览窗口一次即可播放
- Apps Script 模式管理当前已授权用户可访问的文件。弹出 Google 登录并允许后，管理的也是该登录账号可访问的文件。只使用服务账号时，管理共享给该服务账号的文件
- 服务账号下载若被 Google 跳转到 `googleusercontent.com`，扩展会跟一次跳转，且不会把访问令牌带到跳转后的地址。因此清单里重新加入了该主机权限
- 若新按钮未出现，请在 `chrome://extensions/` 重新加载扩展，并强制刷新云端硬盘页面
